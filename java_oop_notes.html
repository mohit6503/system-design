Java OOP complete notes covering static members, polymorphism, encapsulation, abstraction, and access modifiers

Static members
1 A non-static (instance) method cannot directly call a static method on the same class through an instance reference alone — if you need to call it from an instance context, use the class name explicitly: ClassName.staticMethod(). Non-static members belong to an object; static members belong to the class.
2 Static members share a single copy of memory across all instances. Changing a static field from one object changes it for every object.
3 this cannot be used inside a static method. this refers to the current object, but static methods have no object context — they exist before any object is created.
4 Static members can be accessed without creating an object: ClassName.member
★ An inner class can be static. An outer (top-level) class cannot be static — outer classes are always either public, package-private, abstract, or final.

Method overriding
Which method runs depends on the actual object (not the reference type) — resolved at runtime.
▸ Method overriding — the call is resolved based on the actual (runtime) object. E.g. if Animal a = new Dog(), calling a.sound() runs Dog's version. This is true runtime polymorphism. Achieved via: concrete class → abstract class → interface.
▸ Method hiding — applies when the method is declared static. The call is resolved based on the reference type, not the actual object. Static methods cannot be polymorphically dispatched.
3 Three ways to achieve runtime polymorphism in Java:
1. Concrete class (IS-A) 2. Abstract class 3. Interface
Encapsulation
✦ Encapsulation bundles data (fields) and the methods that operate on that data inside a single class, and hides the internal state from outside code.
How to achieve it
• Declare fields as private
• Expose public getter/setter methods
Why it matters
Private fields cannot be accessed directly from outside — all operations go through controlled methods, protecting data integrity.
Abstraction
✦ Abstraction hides implementation details and only exposes what is necessary. The caller knows what a method does, not how.
▸ Using an interface: Define the contract in an interface, implement it in a concrete class, then assign: Interface obj = new ConcreteClass(). The reference type is the interface, the actual object is the implementation — keeping the implementation hidden to the caller.
! Abstract class rules:
Cannot instantiate (no new) Abstract method cannot be static or final Abstract method must be inside abstract class
Access modifiers
public
Accessible everywhere — any class, any package.
private
Accessible only within the declaring class. Not even subclasses.
default (package-private)
No keyword written. Accessible within the same package only — including subclasses in the same package, but not subclasses in other packages.
protected
Accessible within the same class, same package, and subclasses — even subclasses in different packages.
↑ Scope order (widest → narrowest): public → protected → default → private
